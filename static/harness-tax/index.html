The Harness Tax

We gave the same model the same coding jobs inside two agent harnesses (the program that drives the model), Claude Code and pi, and ran a taxi meter on each. One of them pays a much bigger fixed fee on every step before it does any work. This page is about how much that fee costs, and whether it fades on longer jobs.

By Swapnil Sharma · @swappysh

Two harnesses, one model

A coding agent is a model plus a harness. The harness is the program around the model. It writes the system prompt, defines the tools (run a shell command, edit a file), runs the loop, and decides what the model sees on each step (one step is one model call). We held the model fixed at Claude Opus 5.5 with high reasoning effort, and swapped only the harness.

Claude Code is Anthropic's own agent. It ships a long system prompt and a big tool kit: a todo list, sub-agents, web fetch, careful rules about git. pi, by Mario Zechner, goes the other way. Its prompt fits on a page and it has four tools. Here is how much text each one sends on its first model call, before the model has done any work, measured from our runs:

Tokens of context on the first model call, median over the main-round runs: system prompt, tool definitions, the task prompt and any instruction file in the repo. The task prompt and repo are the same for both. One repo (markdown-it-py) has a long AGENTS.md that adds about 6k to both sides.

The model is stateless. On every step the harness sends the whole conversation again, starting with that pack. Prompt caching makes the repeat cheap: a cached token costs $0.20 per million, a twentieth of a fresh one. But an agent takes many steps ( model calls in a typical run here), and the context grows on each one. The question is whether this fee shows up on the bill.

Two things stand out once you watch a few. The meters climb in steps, one per model call, and the big steps are the calls where the model writes a lot. And the two runs rarely take the same path, even on the same task. Those choices move the bill too, as the next section shows.

Why the tax should fade on long jobs

The fee is fixed per step, so it adds up in a straight line. But each step also rereads everything said so far, and that part grows with the length of the job. On a short job the fixed fee is a big share of the bill. On a long job the growing conversation and the model's own output take over, and the fee's share shrinks. What the tests couldn't tell us

Other limits:

  • A small sample: six Python tasks, three runs each per harness. Three are real bug fixes from open-source projects, merged after the model's training cutoff but still public. The other three are synthetic tasks, written by a Claude agent. Each per-task median rests on three runs.
  • The replay also has three small pilot tasks, run before the main round. They are not in the scorecard or the numbers above.
  • The runs shared one /tmp folder. On the markdown-it-py task, four later runs (two per harness) reused a JavaScript library the first run had installed there, so those four may be a little cheap and quick.
  • Some runs used the network: all six inflect runs read the maintainer's blog page on project layout, one Claude Code run on the markdown-it-py task installed the JavaScript markdown-it library, and one on the boltons task installed pytest. Runs on both sides pulled dev tools such as ruff and the mypy type checker through uvx, and the logs show mypy downloads in one Claude Code run and two pi runs. No run fetched the upstream fix.
  • One model. A different model, or a newer pi that knows about this model's adaptive thinking, could change the picture.
  • The graders are from the same model family as the agents.
  • Everything ran on one machine through one API route, at most two runs at a time, with launch order alternated.

How we ran it

The plan, the tasks, the metrics and the bar for calling a winner were written down before any paid run. One change came after the first two runs, when only their cost had been seen: they cost more than expected, so we changed the rule for the number of runs per task to fit the budget, and added a hard stop at $37. Both harnesses ran headless with stock settings, all permissions allowed, a fresh copy of the repo, the same prompt, and a 30-minute limit. Nobody nudged them. Cost is recomputed from each harness's own token log with one price table: $4 per million input tokens, $20 output, $0.20 cache read and $5 cache write. Both harnesses' own totals matched ours.
